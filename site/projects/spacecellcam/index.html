02 / WALKTHROUGH

實作拆解

為什麼先讓相機待機，再把照片寫入 SD？

  1. 穩定畫面再取像

    點亮 LED 後等待 300 ms，首次取像進行中央區域 AF，後續沿用鎖定焦點。丟棄一張過渡影格，再取得最終 QSXGA JPEG，避免把恢復中的畫面直接保存。

  2. 把影像所有權交給 PSRAM

    取得 JPEG 後先複製到 PSRAM，再歸還相機 frame buffer。OV5640 接著進入 standby，SD 寫入使用的是獨立影像副本，不再占用相機緩衝。

  3. 完成檔案再確認保存

    以暫存檔寫入、重新命名及大小核對處理存檔；每 500 張分一個目錄，開機從 SD 恢復編號。write short 或 size mismatch 屬存檔問題，不能只憑拍攝成功就宣稱檔案完整。

這個順序把照明、相機活躍時間與 SD 延遲分開。它解釋了韌體的資源安排，但實際節能幅度仍需獨立電流量測；ESP32 內部溫度也不能當作鏡頭或感測器溫度。

03 / PURPOSE

目的與用途

長時間生物觀察需要穩定的取像順序與可保存的影像。這個韌體將相機、LED、記憶體和 SD 儲存排成明確週期，並透過日誌區分對焦、取像、待機與寫檔問題。

04 / ARCHITECTURE

系統架構

01

照明與時序

LED 預熱和相機 wake 決定開始擷取前的狀態。

02

光學與相機

OV5640 AF 在第一次取像建立焦點，後續沿用鎖定狀態。

03

記憶體

PSRAM 保存 JPEG 副本，讓 frame buffer 可先歸還。

04

儲存

microSD 暫存檔、rename 與大小檢查完成影像保存。

05 / WORKFLOW

操作流程

01喚醒與照明

目前設定目標週期為 10 秒、XCLK 為 20 MHz，先喚醒感測器並開啟 LED，等待 300 ms 讓照明與曝光穩定。這些是設定值。

02對焦與擷取

第一次使用中央區域自動對焦並鎖定；後續擷取重用焦點，丟棄一張過渡影格，再取得 QSXGA JPEG。

03歸還緩衝區

先將 JPEG 複製到 PSRAM，再歸還 camera frame buffer，讓相機能進入 standby，之後才處理 SD 寫入。

04寫入與檢查

影像先寫暫存檔，再重新命名並確認檔案大小。每個 bucket 保存 500 張；開機時回復編號以避免覆寫既有影像。

06 / DECISIONS

設計選擇

重用焦點的取捨

固定場景可省去每次重新搜尋焦點，但目標距離變動時可能失焦，需以照片與日誌一起判讀。

記憶體換取流程解耦

PSRAM 的 JPEG 副本增加暫時記憶體需求，讓 SD 寫入不必延長 LED 點亮及相機活躍時間。

保存失敗的線索

對焦失敗、frame timeout、短寫入與大小不符各有日誌，方便定位問題發生在哪一層。

07 / ANALYSIS

分析與判讀

寫檔與取像分開的好處

先歸還 frame buffer 並待機，能讓較慢的 SD 寫入與相機資源解耦；代價是 JPEG 副本佔用 PSRAM。

固定焦點依賴固定場景

reuse locked focus 紀錄說明走了重用路徑；仍需看照片清晰度，才能知道目標距離與實際焦點是否相符。

檔案完整性有不同層次

寫入大小檢查能識別短寫入，但無法單獨證明 JPEG 可解碼、影像清楚或長時間沒有漏拍。

08 / REPRODUCE

閱讀與重現

  1. 準備 XIAO ESP32S3、OV5640 AF、microSD 與穩定供電，依 repository 的 platformio.ini 建置。
  2. 記錄首次及後續擷取日誌，確認 AF 搜尋與重用路徑不同。
  3. 固定場景後改變目標距離，比對照片清晰度與日誌；另檢查 SD 檔案大小、編號及重新開機後是否覆寫。

09 / LIMITS

範圍與限制

standby／wake 時的 VCM 聲音不等於重新對焦；ESP32-S3 內部溫度也不是 OV5640 或馬達溫度。專案名稱不表示已完成太空環境或在軌驗證。
