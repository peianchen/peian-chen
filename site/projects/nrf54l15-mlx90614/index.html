01 / EVIDENCE

成果與圖像

已提供的實作

公開原始碼包含接腳配置、BLE 特徵、週期取樣與即時量測控制。

既有功耗紀錄

LOW_POWER_ANALYSIS 記錄起始測試約 5.02 V、3.5 mA。此數值屬當時供電與設定，不能視為目前版本優化後的電流。

估算的用途

以 0.66 Wh／720 h 換算約 0.92 mW，說明 30 天目標的平均功率預算；電池容量與負載條件會影響可用能量。

02 / WALKTHROUGH

實作拆解

休眠等待時，手機如何要求再量一次？

  1. 連接感測器

    公開專案以 XIAO nRF54L15 的 i2c22 讀取位址 0x5A 的 MLX90614，SDA 為 P1.10、SCL 為 P1.11。這份接線只適用於此公開板型設定，不代表其他 Raytac 或客製板版本。

  2. 交換明確的 BLE 資料

    裝置名稱為 Thermo-MLX，服務 0xFFF0；溫度由 0xFFF1 以 ASCII 攝氏數字傳送，例如 26.34 是格式示例。控制特徵 0xFFF9 接收 sample 或 measure，要求立即取樣，不改變正常 60 秒間隔。

  3. 保留可喚醒的通訊路徑

    兩次量測間主執行緒等待 semaphore，讓系統進入 System ON idle，同時保留 BLE。若直接改成 System OFF，手機就無法經原 BLE 連線要求量測；量測版也關閉 UART 與診斷 LED，避免影響功耗觀察。

設計取捨在於『保持手機可控制』與『降低平均耗電』。電池壽命預算必須和實際電流紀錄分開，不能把理論預算寫成已達成的續航。

03 / PURPOSE

目的與用途

在保留手機連線與操作的條件下，安排間歇取樣及低功耗等待。

04 / ARCHITECTURE

系統架構

01

感測介面

MLX90614 透過 i2c22 讀取環境與物體溫度；overlay 將 SDA／SCL 對應到 P1.10／P1.11。

02

取樣工作

Zephyr 主執行緒以 semaphore timeout 等待，定期或收到手機命令時執行一次讀值。

03

通訊服務

自訂溫度、狀態與控制特徵分別處理讀值通知及即時量測要求，保持資料與命令方向清楚。

04

電源管理

讀值前後 resume／suspend I²C，關閉預設診斷輸出；BLE 保留在 System ON idle 的操作流程。

05 / WORKFLOW

操作流程

01啟動周邊與廣播

檢查 I²C 裝置並建立 BLE 服務，等待手機連線。

02等待取樣事件

正常週期為 60 秒；寫入 sample 或 measure 可提前喚醒工作，不改變週期設定。

03取得並傳送溫度

喚醒 I²C、讀取感測器，將攝氏數值以 ASCII payload 提供給手機。

04返回等待

暫停 I²C 並阻塞執行緒，讓作業系統在 BLE 可用的條件下安排省電。

06 / ANALYSIS

分析與判讀

取樣頻率不是唯一耗電來源

將 10 秒改為 60 秒可降低讀值事件頻率，但無線連線、感測器待機與板上電源電路仍可能主導平均耗電。比較版本時應保持供電位置和量測設定一致。

可連線與最深睡眠的取捨

手機即時命令需要 BLE 持續可用，因此以阻塞等待搭配 System ON idle。實際續航需同時觀察廣播、連線和讀值三種狀態。

溫度值的意義

物體溫度與環境溫度是不同量；感測距離、視野與目標表面會影響讀值，通訊成功本身不代表校正完成。

07 / REPRODUCE

閱讀與重現

  1. 依 README 連接 XIAO nRF54L15 與 MLX90614，核對感測器位址及 pull-up。
  2. 使用相容 NCS 環境建置 xiao_nrf54l15/nrf54l15/cpuapp，核對 overlay。
  3. 以相容 BLE client 觀察通知並寫入 sample，比對週期取樣和即時取樣路徑。
  4. 分別量測廣播、連線與讀值時的電流，記錄供電端與韌體設定。

08 / LIMITS

範圍與限制

使用 System ON idle 保留 BLE，不是 System OFF。電池壽命估算、實際電流與量測準確度需分別判讀。
