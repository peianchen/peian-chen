NYCU-AFPGA

從組合邏輯、FSM、RAM、簡易處理器到 DE1-SoC HPS/Qsys 整合的八組詳細實驗文件。

01 / PURPOSE

目的與用途

循序理解數位邏輯、記憶體與處理器架構，再延伸至 HPS 與 FPGA 的軟硬體介面。

02 / ARCHITECTURE

系統架構

01

數位邏輯

Lab 1–4 從組合與循序邏輯走到算術、暫存器及 FSM。

02

資料與指令

Lab 5–6 整合 RAM、ROM 與簡易處理器，觀察資料路徑與控制。

03

SoC 介面

Lab 7–8 將 Linux userspace、Qsys address map 與 HPS-to-FPGA bridge 連接。

04

可觀察輸出

LED、七段顯示、RTL Viewer 與歷史波形提供不同層次的驗證線索。

03 / WORKFLOW

操作流程

01確認實驗與來源

由八組 Lab 索引定位 Quartus 專案、top-level 與說明。

02理解邏輯

將輸入、控制與輸出對照測試矩陣及 HDL。

03工具建置

核對裝置、腳位與 IP 路徑，依工具相容性進行 synthesis 或 compilation。

04對照結果

用波形與原報告照片解釋輸出，SoC 實驗另核對軟硬體位址。

04 / EVIDENCE

成果與圖像

八組實驗

公開版保存詳細說明、Quartus／Verilog／HPS source 與經審查的歷史結果圖片。

代表工程重建

README 記錄 Lab 01 Part 01 以 Quartus 25.1 full compilation 完成，0 errors、248 warnings。

Lab 8 控制結果

照片顯示 LED one-hot 移動與往返計數，與 HPS C 程式的暫存器寫入流程對應。

05 / ANALYSIS

分析與判讀

從 LED 看見整條資料鏈

Lab 8 的結果串起 Linux 程式、bridge、Avalon peripheral 與實體腳位。七段顯示的是完整往返次數，並非當前 LED 位置。

等待時間要看全部呼叫

Lab 8 每步同時包含 100 ms 與 1 s 的等待，合計約 1.1 s。只讀單一註解會誤判執行速度。

建置與時序

代表工程可以重建是工具相容性的證據，但該紀錄沒有 SDC／clock constraint，不能由編譯成功推論時序收斂。

06 / REPRODUCE

閱讀與重現

  1. 開啟 Lab 索引並選擇一個完整子專案。
  2. 使用相容 Quartus，先檢查 top-level、device、腳位及相對 IP 路徑。
  3. 依 Lab 測試矩陣對照輸入與輸出；重建時可使用短 ASCII 工作路徑。
  4. Lab 8 需確認 Qsys 與 hps_0.h 位址一致，再分別驗證硬體與 Linux 軟體。

07 / LIMITS

範圍與限制

公開版本排除整份作業報告與個資。歷史實驗照片、代表工程編譯與尚未重做的驗證分別記錄。
