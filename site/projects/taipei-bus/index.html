Taipei Bus Live

台北公車 Live

以臺北市官方動態資料建立公車地圖，提供路線與車牌搜尋、標記聚合、站牌到站預估、收藏，以及依路線線形呈現的短時間位置推估。

01 / PURPOSE

目的與用途

把官方車況快照、路線與站牌資料整合成可互動查詢的地圖。

02 / ARCHITECTURE

系統架構

01

官方資料入口

Node.js 伺服器取得臺北市公車車況、路線、站序與到站預估，對上游請求設定逾時。

02

共用快取

車況使用 1 秒快取，路線／站序索引保存 6 小時，到站預估共用 15 秒快取。

03

位置模型

沿官方 BusShape 匹配進度，以 α-β 濾波修正位置與速度，依信心縮短外插。

04

地圖呈現

MapLibre GL JS 聚合遠景標記，更新可視車點，提供搜尋、收藏、分享及手機資訊卡。

03 / WORKFLOW

操作流程

01取得快照

伺服器共用上游資料，失敗時保留上一份並標示延遲。

02匹配行駛方向

根據線形、方向與上一段進度建立車輛模型，限制離群資料的影響。

03平順呈現

瀏覽器沿短路線折線呈現位置；推估最長 15 秒，之後等待新回報。

04查詢路線與站牌

選車後按需載入路線與站序，站牌預估另以官方結果顯示。

04 / EVIDENCE

成果與圖像

已實作的互動

路線／車牌搜尋、標記聚合、收藏、路線分享及官方站牌預估均有公開程式。

更新成本控制

快照不變時不重建標記，動畫只處理可視車輛與變動車點。

位置顯示範圍

平順移動是依官方回報建立的短時間推估，回報年齡與推估狀態需與地圖一起閱讀。

本次軟體檢查

公開版本 6d9db5e 的 Node 測試套件重新執行，61 項通過、0 失敗。測試涵蓋資料、軌跡、站序、介面及上游處理，不是道路定位精度量測。

本頁以架構、流程與可核對紀錄說明成果；目前未選入足以清楚呈現結果的照片或畫面。

05 / ANALYSIS

分析與判讀

平順不等於更新更快

動畫改善讀取連續性，但不增加官方資料的採樣頻率。資料回報時間和畫面重繪頻率必須分開解讀。

共用快取降低重複工作

多個瀏覽器可以讀取同一份快照，讓上游請求數不直接隨訪客數增加。保留舊快照時也需呈現其年齡。

站牌預估屬另一種資料

路線／站牌 ETA 不等於目前選取公車的精確抵達時間；方向、班次與路況會影響結果。

06 / REPRODUCE

閱讀與重現

  1. 安裝 Node.js 20 以上及依賴，於 repository 執行 npm test。
  2. 以 npm start 啟動伺服器，開啟 localhost:5180。
  3. 搜尋路線、選擇車輛與站牌，核對方向、時間與來源署名。
  4. 比較遠景、近景與 reduced-motion；確認資料延遲時仍能辨識快照年齡。

07 / LIMITS

範圍與限制

開發中。位置推估最長 15 秒，會受回報延遲及匹配信心影響；到站預估不是所選車輛的精確抵達時間。
