02 / WALKTHROUGH

Implementation in focus

Turn one SDK callback into an understandable measurement

  1. Check whether acquisition can start

    HealthSensorManager checks BODY_SENSORS permission, service connectivity and support for SKIN_TEMPERATURE_ON_DEMAND. Missing permission or an unsupported tracker produces an explicit state rather than an indefinite wait for data.

  2. Distinguish success, empty data and errors

    The callback reads the last DataPoint and extracts STATUS, OBJECT_TEMPERATURE, AMBIENT_TEMPERATURE and timestamp. Empty lists have their own state; abnormal status is not accepted as valid temperature, and missing values are not replaced with zero.

  3. Finish the measurement

    A data callback ends the tracker. A separate 30-second limit reports a timeout if no callback arrives. StateFlow exposes readings, callback counts and status to the UI, preserving more context than a single number.

This is a focused sensor-integration project. PPG remains a disabled extension point, not a completed multi-signal health-monitoring platform.

04 / ARCHITECTURE

System architecture

01

User interface

A Kotlin screen exposes a single measurement action and displays temperatures, units, time and status.

02

Service connection

HealthSensorManager coordinates Samsung Health Platform connectivity, permissions and tracker support.

03

Measurement lifecycle

SKIN_TEMPERATURE_ON_DEMAND stops after one callback, giving the operation an explicit resource boundary.

04

Extension scope

Green, red and infrared PPG entry points are retained but disabled by default.

05 / WORKFLOW

Operating workflow

01Check the platform

Use a compatible physical Galaxy Watch and SDK; resolve service and permission state.

02Request one reading

Measure starts the on-demand tracker and the view waits for data.

03Handle the callback

Receive wrist and ambient temperatures with a callback timestamp or error.

04Stop and present

Stop the tracker and retain the reading for inspection until the next action.

06 / ANALYSIS

Analysis and interpretation

Read status alongside values

Missing data can originate in permissions, service state, tracker support or contact conditions. Status distinguishes an unfinished operation from a valid reading.

An explicit single-shot boundary

Stopping after one callback simplifies operation, but does not establish continuous logging or day-night trends.

Physical-platform dependencies

The Samsung AAR and platform policy are runtime requirements. An emulator UI cannot verify the watch sensor.

08 / LIMITS

Scope and limitations

The README targets Galaxy Watch6 or newer physical devices. The SDK AAR, permissions, and platform policy requirements must be satisfied separately. Not for medical diagnosis.
