ThermoPatch

Connecting sensor patches into one usable system.

01 / CONTEXT

Purpose

Multi-location sensing requires device identity, location mapping, connection state and an unambiguous update target. ThermoPatch brings these operations into one Android application for connecting patches, observing readings and selecting a device for maintenance.

02 / WORKFLOW

How it works

Select a stage to explore its role.

01Acquire and transmit

Companion nRF52840 firmware exposes temperature, standard Battery Service and Nordic DFU interfaces. The public repository primarily contains the Android app; firmware is maintained separately.

02Track state and location

BluetoothViewModel manages scanning, GATT connections and notifications. DeviceViewModel transforms payloads into device state and six body locations: head, chest, both arms and both legs.

03Display and synchronize

Jetpack Compose presents readings, battery and charging state; aggregated data is sent to Firebase Realtime Database. Connection, display and cloud persistence are separate stages to verify.

04Maintain firmware

Settings provides a connected-device selector and DFU ZIP selection. MyDfuService and Nordic callbacks report update progress. Explicit targeting reduces ambiguity when multiple devices are connected.

03 / DECISIONS

Design decisions

Separate body location from connectivity

The UI answers where a reading comes from; the BLE layer manages the physical connection. Keeping these responsibilities distinct helps diagnose replacement and disconnection.

Give DFU its own workflow

Keep file selection, target selection and progress together so maintenance is separate from everyday monitoring.

Keep release boundaries clear

This page describes the public nRF52840 app. Room persistence and queued multi-device synchronization in the later private V2 research are not attributed to this release.

04 / EVIDENCE

Results and evidence

Public implementation

Source and procedures cover scanning, notifications, body-location data, battery state and DFU.

Archived test evidence

The repository includes a v1.0.1 unit-test summary with 1 test and 0 failures. That summary does not establish multi-device BLE stability, physical DFU reliability or temperature accuracy.

Hardware verification needed

Connection stability, calibration, recovery, interrupted updates and long-duration recording require tests with identified phones, firmware and sensor nodes.

05 / REPRODUCE

Reproduce the workflow

  1. Prepare the Android SDK, JDK and Gradle environment specified by the repository and configure your own Firebase project.
  2. Run assembleDebug and testDebugUnitTest to check the build and software tests separately.
  3. Use compatible physical devices to inspect payloads, location mapping and battery state. DFU packages must match the target board and bootloader.

Scope and limitations

This is a research sensing integration project. Six display locations do not establish reliable concurrent operation of six devices, clinical suitability or medical measurement accuracy.
